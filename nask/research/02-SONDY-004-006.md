# Sondy 004–006 — co sprawdzone i co z tego wynika

Trzy przebiegi, **68 sond, wszystkie GET, read-only, hosty wyłącznie z zakresu**.
Wynik: **0 potwierdzonych podatności**. Ten dokument jest równie ważny jak
znalezisko — mówi, czego nie ma sensu testować dalej.

Dane: `nask/reports/probe-run004b.json`, `probe-run005.json`, `probe-run006.json`.
Każda sonda ma odpowiedź odejmowaną od **catch-all tego hosta** (losowa
nieistniejąca ścieżka), więc serwis zwracający 200 na wszystko nie daje
fałszywych trafień.

---

## 1. `bezpiecznymiesiac.pl/download-file/?fileUrl=` — ZABEZPIECZONY

Najmocniejszy trop z mapy: endpoint czyta plik z dysku po ścieżce (kontrola
zwraca prawdziwy PDF, 603 KB, `Content-Disposition: attachment`).

Sprawdzone 20 wariantów:

| Wariant | Wynik |
|---|---|
| `/media/.../plik.pdf` (kontrola) | **200**, 603 523 B, `application/pdf` |
| `/etc/passwd`, `/proc/version`, `/etc/hostname`, `/etc/os-release` | **404**, 14 B — „File not found" |
| `../../../../etc/passwd`, `%2e%2e%2f…`, `..%2f…`, `%252e%252e…`, `....//` | **400**, 30 B — „Nieprawidłowe żądanie pliku" |
| `..%5c..%5c` (Windows), `file:///etc/passwd`, `/media/./../../` | **400**, 30 B |
| `https://science.nask.pl/robots.txt`, `//science.nask.pl/…` | **400** / **404** |
| `http%3A%2F%2F…`, `https:%2F%2F…`, `HTTPS://…` (obejście filtra) | **400**, 30 B |

**Wniosek:** filtr dekoduje wartość **przed** sprawdzeniem i odrzuca schematy
oraz `..` niezależnie od kodowania. Ścieżki absolutne bez kropek dostają 404,
czyli wartość jest doklejana do katalogu mediów. Osie ataku: kodowanie,
schemat, ścieżka absolutna, backslash — **wszystkie zamknięte**.

## 2. `science.nask.pl/api/media/<ścieżka>` — NIEROZSTRZYGNIĘTE

Kontrola działa (200, 182 155 B, JPEG), więc proxy istnieje. Traversal w
**ścieżce** jest jednak **niemierzalny tym klientem**: biblioteka HTTP
normalizuje segmenty `..` przed wysłaniem. Dowód z logu:

```
sci-traversal-enc  error: error sending request for url (https://science.nask.pl/etc/passwd)
```

Zadanie nigdy nie dotarło pod `/api/media/…` — zostało znormalizowane do
`/etc/passwd`. Dlatego w przebiegu 007 testuję warianty `..%2f` i `%252e%252e%252f`,
które parser zostawia nietknięte.

## 4. CORS — BRAK ODBICIA na 8 endpointach

`Origin: https://evil.example` wysłany do `zglos/api/sendForm`, `dns/api/who-is-xml`,
`116sos/api/announcements`, `dataannotation/api/v1`, `pllum/api/_content/query`,
`oad/api`, `science/wp-json`, `dyzurnet/api`, `bezpiecznymiesiac/download-file`.

**Żaden nie zwrócił `Access-Control-Allow-Origin` równego wysłanemu Origin.**
Jedyny `Access-Control-Allow-Credentials: true` (HIVE, 404) występuje bez
`ACAO`, czyli jest bezużyteczny. Klasa CORS na tych hostach — zamknięta.

## 5. Pozostałe ustalenia

- **HIVE** (`dataannotation.pllum.org.pl`) to SPA React Routera
  (`create-tsrouter-app`): każde nieznane ścieżki → 200 + ten sam HTML 713 B.
  `/api/v1/` → 404 JSON (22 B), więc API istnieje, ale nie ma listingu korzenia.
  `/openapi.json` i `/docs` trafiają w catch-all → brak schematu.
- **`pllum.org.pl/api/_content/query`** zwraca publiczne treści Nuxt Content
  (`_draft:false`, 9 543 B). To działanie zgodne z projektem, nie wyciek.
- **`dns.pl/api/*`** → 404 z 41 KB strony serwisu. Literały `/api/…` z bundla
  nie odpowiadają realnym trasom.
- **`116sos.pl/api/*`** → 502 nginx. Backend nie odpowiada; to awaria, nie luka.
- **`zglos-dezinformacje/api/sendForm`** → **405** na GET, czyli endpoint
  istnieje i przyjmuje tylko POST. Klient wymaga reCAPTCHA v3.

## 7. Wniosek dla strategii

Po 68 sondach obraz jest taki: **publiczna powierzchnia NASK jest utwardzona
na klasy dostępne bez kont** (trawersal, SSRF przez proxy, CORS, optymalizator
obrazków). To nie znaczy „nie ma luk" — znaczy, że **klasy bezstanowe bez
uwierzytelnienia zostały sprawdzone** w najważniejszych miejscach.

Pozostają dwie drogi: (a) głębsze pliki konfiguracyjne/backupy i warianty
kodowania (przebieg 007), (b) **część zalogowana** — IDOR/BAC w HIVE i
formularzu, gdzie bez własnych kont i przeglądarki nie wejdę.
